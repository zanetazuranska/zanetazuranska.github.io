Mario made by Zengine

Zengine is a 2D platformer engine developed in C++ using SFML. I wanted to dig into low-level game engine architecture and really understand what goes on beneath the surface. My focus was making something modular and scalable for 2D games.

To show what Zengine can do, I made a Mario-inspired prototype. It`s not a remake but my own spin on classic platformer, using gameplay systems I built myself.

Project Collaboration ▾

Project Overview

I created this project as part of the Girls in Games initiative, in collaboration with CD PROJEKT RED. I worked under the mentorship of Przemysław Machniewski, who helped guide me through all the technical challenges.

This wasn`t typical team effort. I worked alone, designing and coding every part of the engine and game. My mentor provided regular feedback and code reviews, which really pushed me to keep improving.

Development Notes ▾

Project Challenges

Building a custom game engine was a completely new experience. Especially because I had a very short time to do it. The biggest challenge was designing a solid architecture while simultaneously learning how engine systems interact with one another.

  • Figuring out engine architecture as I went (lots of changes as I learned more about what works).
  • Creating level loading and scene transitions that made adding content easy and efficient.
  • Separating the engine from the game later in development which turned out to be much more work than if I`d done it from the start
  • Completing it all within a short mentoring program, picking up new concepts as fast as I could.

How I Solved It

The way I worked changed a lot as I went along, mostly thanks to ongoing feedback from my mentor, Przemysław Machniewski. His guidance helped me not just write better code but also understand engine development practices.

  • I refactored the architecture several times as I added new features, ending up with something much cleaner.
  • I used the Tiled level editor and built a custom loader to import JSON map data, making maps easy to edit and reuse.
  • Step by step, I separated engine modules from game-specific code until Zengine could stand on its own.
  • Regular mentoring sessions and code reviews helped me catch and fix architectural issues early.

What I Would Do Differently

If I started the project again, I would separate the engine from the game from the very beginning. It would`ve saved hours of refactoring and made the whole structure more solid.

Still, working on this project completely changed how I think about game engines. I have a much deeper understanding of how their internal systems work together. And honestly, getting to learn from Przemysław Machniewski was incredibly valuable, and I would gladly take on a similar challenge again.
