Mario made by Zengine

Zengine is a custom-built 2D platformer engine developed in C++ using SFML, created to explore low-level game architecture and systems design. The project was designed as a modular and scalable foundation for 2D games, with a strong focus on performance, flexibility, and clean structure.

To demonstrate the engine’s capabilities, I developed a playable Mario-inspired prototype. This version reimagines classic platforming mechanics with my own approach to gameplay systems and implementation.

Project Collaboration ▾

Project Overview

The project was created as part of the Girls in Games initiative, in collaboration with CD PROJEKT RED and under the mentorship of Przemysław Machniewski.

Unlike my previous team projects, this was an individual project where I was responsible for designing and implementing every system myself while receiving regular technical guidance and code reviews from my mentor.

My Role

Solo Engine Programmer

Engine Overview ▾

Zengine

Zengine was developed as a modular 2D game engine from scratch in C++ using SFML. The goal was to gain a deeper understanding of low-level engine architecture by implementing every core system independently.

  • Input handling module
  • SFML-based rendering system
  • Physics and collision detection
  • Animation system
  • Audio system
  • Multi-map and scene management
  • User Interface framework
  • Debugging tools
  • Custom data structures and utilities

Mario Showcase

To validate the engine architecture, I developed a Mario-inspired platformer entirely on top of Zengine. The prototype served as a practical demonstration of the engine rather than a recreation of the original game.

  • Character movement and jumping mechanics
  • Enemy AI and player interactions
  • Physics and collision handling
  • Animation and audio integration
  • Scene management and UI systems
  • Gameplay implemented exclusively with custom engine components

Development Notes ▾

Project Challenges

Building a custom game engine within a limited timeframe was a completely new experience. The biggest challenge was designing a solid architecture while simultaneously learning how engine systems interact with one another.

  • Designing the engine architecture from scratch without previous engine development experience. The structure evolved significantly throughout the project as I gained a better understanding of system dependencies.
  • Implementing level loading and scene transitions in a scalable way while keeping the workflow efficient for content creation.
  • Separating the engine code from the game itself. This process started relatively late, making the refactoring much more time-consuming than expected.
  • Developing the entire project within a relatively short mentoring program while continuously learning new concepts and development practices.

How I Solved It

The project was developed iteratively with regular feedback from my mentor, Przemysław Machniewski. His guidance helped me improve the architecture and better understand engine development practices.

  • Continuously refactored the engine architecture as new systems were introduced, resulting in a much cleaner and more modular design.
  • Integrated the Tiled level editor into the workflow, allowing maps to be created visually and exported as JSON files. I then implemented a custom world-loading system capable of recreating entire levels from this data.
  • Gradually separated engine modules from game-specific code, refactoring one system at a time until the engine became largely independent of the Mario prototype.
  • Regular mentoring sessions and code reviews helped me identify architectural issues early and apply better practices throughout the project.

What I Would Do Differently

If I started the project again, I would separate the engine from the game from the very beginning. Retrofitting this separation later required a considerable amount of refactoring that could have been avoided with a clearer initial architecture.

Despite that, this project completely changed the way I think about game engines and gave me a much deeper understanding of how their internal systems work together. Working under the mentorship of Przemysław Machniewski was an invaluable experience, and I would gladly take on a similar challenge again.
